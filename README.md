# Reelpick - Movie Recommender (React + Vite)

A complete movie recommendation app with accounts.

- **Poster images and a description for every movie** (images live in `public/posters`)
- **Movie details dialog**, a "Tonight's pick" feature, genre chips, search and sorting
- **Light and dark theme** with a toggle in the navbar
- **Create account / Log in / Log out** with form validation
- **Protected pages**: Discover and Profile need a login; Login and Signup are skipped when you are signed in
- **Per-account picks**: every user has their own liked movies
- **Content-based recommendations** (genre, director, themes)
- **Collaborative recommendations** (what viewers with similar picks liked)
- **Find similar** for any movie, plus search, genre filter and sorting

## Run it

```bash
npm install
npm run dev
```

Open http://localhost:5173. Build for production with `npm run build`.

## Movie images (public folder)

Every movie in `src/data/movies.js` has a `poster` path that points to an image in `public/posters/`, plus a `description`. The 24 starter posters are original artwork generated by `scripts/generate-posters.js`, so the app looks complete with no setup and no internet connection.

- **Use your own images:** put a `.jpg` or `.png` in `public/posters/` and change that movie's `poster` value, for example `poster: "/posters/inception.jpg"`.
- **Add a movie:** add an object to the `movies` array (with `poster` and `description`), then run `npm run posters` to generate artwork for it automatically.
- **Real posters:** if you add a TMDB API key (next section), the real poster is shown first and your local image is the fallback.

Real movie posters are copyrighted, so they are not bundled. Only add images you have the right to use.

## Real posters and live recommendations (TMDB API)

The app works without any setup, using the local poster images and its built-in recommender. To turn on real posters and live recommendations from [The Movie Database (TMDB)](https://www.themoviedb.org/):

1. Create a free account at https://www.themoviedb.org and open **Settings > API**.
2. Request an API key. Copy the **API Key (v3 auth)**. The long **API Read Access Token** also works.
3. In the project folder (next to `package.json`), create a file named `.env`. You can copy `.env.example`:
   ```
   VITE_TMDB_API_KEY=paste_your_key_here
   ```
4. Stop the dev server (Ctrl+C) and run `npm run dev` again. Vite only reads `.env` when it starts.

What you get once the key is set:

- **Real movie posters** on every card, found by searching TMDB for each movie in `src/data/movies.js`. Results are cached in the browser, so later visits load instantly. If TMDB is unreachable, the local image is used.
- **More to explore**: live suggestions from TMDB's recommendations endpoint, based on the movies you liked.
- **Trending this week**: what people are watching right now.

The `.env` file is listed in `.gitignore`, so do not commit it. Because this is a browser-only app, the key is visible to anyone who opens the site's network tab. That is normal for TMDB's free keys, but a public site should call TMDB through a small backend instead.

### Download the real posters into the public folder

If you would rather have the real poster files saved in `public/posters` (so they work even without a key afterwards):

```bash
npm run posters:download
```

This reads your key from `.env`, downloads a poster for every movie, and updates the `poster` paths in `src/data/movies.js`. Restart the dev server afterwards. Posters that cannot be found keep their current image. These posters come from TMDB and are for personal or learning use.

## Important: how accounts work

This is a front-end-only demo. Accounts are saved in the browser's `localStorage`, and passwords are salted and hashed (SHA-256) before saving. That is fine for a class project or prototype, but:

- Accounts exist only in the browser where they were created.
- A real product needs a backend (for example Node + Express + a database), a slow password hash like bcrypt or argon2, and secure session tokens.

To move to a real backend, replace the `signup`, `login`, `logout` and `deleteAccount` functions in `src/context/AuthContext.jsx` with API calls. The rest of the app will not need to change.

## Deploying

Because the app uses client-side routes, configure your host to serve `index.html` for unknown paths (on Netlify add a `_redirects` file containing `/* /index.html 200`; on Vercel add a rewrite to `/index.html`).

Open `src/data/movies.js` and add an object to the `movies` array with a unique `id`, `title`, `year`, `genres`, `director`, `tags` and `rating`.
